# Antigravity Prompt Pack — TinySteps Match Illustrations

> **Scope:** Generate illustration files only. Do not change the app UI, lesson JSON, database, Supabase Storage, or manifests in this run.
>
> **Inventory:** 525 Match items across 23 batches of ≤25 (Starters 90/4, Movers 90/4, Flyers 120/5, PET 120/5, KET 105/5). Batches never mix levels, so each QA pass stays visually coherent.
>
> **Source of truth:** `tinysteps-data/match-illustration-batches/batch-<NN>-<level>.json`, generated by `python3 tinysteps-data/generate_match_illustration_queue.py`. Antigravity reads these files verbatim — it does **not** parse lesson JSON or derive asset keys/paths itself. That was the root cause of a real bug found 2026-07-14: a hand-derived key used the bare lesson filename number ("001") instead of the lesson's content id, which collides across all 5 levels (every level has its own `lesson-001.json`) and would have silently overwritten Starters' images with Movers'/Flyers'/etc. The generator now computes every path once, correctly, from the actual JSON.

## How to run

**Before every batch**, regenerate the queue so `generated` flags reflect reality (picks up anything deleted after a QA rejection):

```bash
python3 tinysteps-data/generate_match_illustration_queue.py
```

It prints which batch to run next. Start a **new Antigravity task per batch**. Paste the **Shared instruction** once, then the batch's **file path**. Do not start the next batch until a human has QA'd the previous one.

### Shared instruction (paste every time)

```text
You are generating classroom-friendly visual assets for the TinySteps English-learning app.

Repository root: /home/hoang-xuyen/Projects/tinysteps-concept
I will give you the path to a batch JSON file, e.g.
  tinysteps-data/match-illustration-batches/batch-01-starters.json

Read that file. It is a JSON object: { "batch": "01", "level": "starters", "items": [...] }.
Each item already has the exact fields you need — assetKey, outputPath, imageHint,
correctAnswer, siblingAnswers, generated. Do NOT derive assetKey or outputPath
yourself from lesson JSON or filenames — use the item's own "outputPath" field
verbatim as the save location, and its "assetKey" verbatim in your report.

Skip any item where "generated" is already true (already produced; if it was QA
rejected, it will have been deleted and will show as false the next time the batch
file is regenerated — do not skip based on your own judgment).

For every item where "generated" is false:
1. Use "imageHint" as the scene brief, improved as needed for a clear teaching
   illustration.
2. The image must depict ONLY "correctAnswer"'s concept. Do not depict, hint at, or
   include any of the item's "siblingAnswers" — those are the OTHER answer options in
   the same exercise, and including them would let a learner guess without knowing the
   target word.
3. Save as a 1:1 square WebP at the item's "outputPath" (relative to repo root).

Visual direction:
- warm, polished, child-friendly editorial illustration; clean shapes, gentle texture, soft daylight, consistent palette
- the target concept must be the single largest and clearest visual element
- for a simple concrete-object hint (book, pen, marker, etc.): render ONLY that object
  on a plain/minimal surface. Do not add decorative page illustrations, animals,
  plants, trees, or other iconography onto or around it — every extra recognizable
  object is a potential distractor. (A real rejected example: an "open textbook" hint
  rendered with a tree, two birds, a cat, and a sun icon drawn onto the pages — reject.)
- diverse people where people are necessary; age-appropriate and culturally neutral classroom context
- square 1:1 composition; no frame, no border, no text area

Hard restrictions / negative prompt:
- no readable text, letters, words, numbers, labels, signage, UI text, worksheets with readable writing, logos, watermarks, brand marks, or QR/bar codes — this includes abstract squiggles that closely mimic handwriting; keep any background scribbles clearly non-letter-like or omit them
- do not include siblingAnswers' concepts anywhere in the artwork
- no collage, split-screen, infographic, diagram, or multiple-panel layout unless the scene genuinely requires a single unambiguous visual symbol
- when imageHint asks for a text card, calendar, agenda, ticket, chart, checklist, phone screen, menu, receipt, or board: replace readable content with abstract, non-readable marks or a clear non-text visual metaphor

For each item you process, write one row to a batch report at:
  docs/generated-illustrations/batch-<NN>-report.md
Columns: assetKey | imageHint | outputPath | status | qa
"status" (you fill this) is exactly one of: Generated (file written) | Skipped
(already generated) | Failed (explain why in an extra note). Only write a row as
Generated after the file actually exists on disk at outputPath.
"qa" (leave as "Pending" — a human fills this in after reviewing, never you) is one of:
Pending | Approved | Rejected: <reason>. The manifest builder only picks up rows marked
Approved, so nothing reaches the app until a human has actually looked at it.

Before generating, list the exact assetKeys you are about to process (only the
"generated: false" ones). After generating, verify every expected .webp exists and
explicitly call out any missing/failed ones. Do not touch files outside this batch's
outputPaths.
```

### Running a batch

Paste after the shared instruction:

```text
Process tinysteps-data/match-illustration-batches/batch-01-starters.json — this is batch 01.
```

Repeat for `batch-02-starters.json` … `batch-23-ket.json` (file names printed by the generator; run it again after each QA pass to see what's next).

## Human QA gate — required after every batch, per image

Approve an image only when all of these hold:

1. Target concept (`correctAnswer`) is immediately obvious at mobile size.
2. No readable text, accidental letters, numbers, branding, or text-mimicking scribbles.
3. None of `siblingAnswers`' concepts appear anywhere in the image.
4. 1:1 WebP exists at the exact `outputPath` from the batch JSON.
5. Style matches the approved reference set (warm, editorial, single clear subject).

**Reject → delete the file.** The next `generate_match_illustration_queue.py` run will
automatically re-queue it (its `generated` flag flips back to false) — no manual
bookkeeping needed. Do not upload approved assets to Supabase Storage yet; that's a
separate step (`tinysteps-app/scripts/build-illustration-manifest.mjs` then
`upload-illustrations-to-storage.mjs`, run only after QA — see deployment-guide.md).

## Suggested cadence

QA time, not generation time, is the real constraint — budget for reviewing every
image individually, not rubber-stamping a batch. A sampled pass on the very first
proof-of-concept batch found roughly 1-in-3 images needed rejection, so expect real
back-and-forth, especially early on while the prompt is still being tuned.

- **2 batches/day** (~50 images, ~15-30 min of focused QA) → 23 batches in **~12 days**.
- Front-load Starters (4 batches) since teachers will encounter it first and it
  calibrates the visual style for everything after.
- The pipeline is fully resumable at any point — stopping for a few days and picking
  back up just means re-running the generator to see what's still pending.
